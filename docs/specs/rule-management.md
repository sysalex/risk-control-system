# 规格：规则管理 API

> 轻量 SDD 产物，阶段 3 规则管理模块

---

## 目标

提供风控规则的 CRUD 管理能力，支持规则的创建、查询、更新、删除、启用/停用。

## 非目标

- 规则引擎的执行与匹配逻辑（规则引擎在后续阶段实现）
- 规则条件表达式的结构化解析与校验（当前阶段保持 JSON 字符串存储）
- 审计日志的自动注入机制（阶段 6 统一实现，但规则变更需预留审计接入点）

## 验收标准

1. `/rules` 端点支持分页列表查询、创建、详情获取、更新、删除
2. `/rules/{id}/enable` 和 `/rules/{id}/disable` 端点可切换规则启用状态
3. 规则名称全局唯一，创建或更新时冲突返回 409 Conflict
4. 规则启停、创建、更新、删除仅允许 ADMIN 角色操作
5. 规则列表和详情允许所有已认证用户查看
6. 测试覆盖率满足分层要求：`risk-application` ≥ 85%，`risk-interfaces` ≥ 70%

## 默认假设

1. `conditions` / `actions` 字段在 DTO 和 Entity 层均使用 `String` 类型存储 JSON 文本，规则引擎阶段再演进为结构化对象
2. 权限模型：`list` / `get` 允许所有认证用户；`create` / `update` / `delete` / `enable` / `disable` 要求 `ADMIN`
3. 规则删除为物理删除（实体无 `deleted` 软删除字段），删除操作由阶段 6 审计日志记录
4. 分页参数统一为 `page` / `limit`，默认 `page=1`，`limit=20`，最大 `limit=100`
5. 规则优先级默认值为 `100`，数值越小优先级越高；优先级相同时按 `created_at` 排序
6. 响应体中 `conditions` / `actions` 以原始 JSON 字符串返回，由前端自行解析展示

## 待确认问题

**无待确认问题。** 所有边界均可从现有规范（`domain-model.md`、`api-spec.md`、实体代码）推断出合理默认值。
